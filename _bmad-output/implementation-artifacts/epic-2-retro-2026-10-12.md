### 1. Planning docs still contradict the as-built droplet (spec reconciliation)

- **Token variable:** `SPEC.md:19,65` ("`DIGITALOCEAN_TOKEN` is the token env var"), `platform-decisions.md:25,36`, `stories.yaml:2,4` still name `DIGITALOCEAN_TOKEN`; the shell and the devcontainer use `DIGITALOCEAN_ACCESS_TOKEN` since `a12d7ff`/`6f8671f`. Only the epics file and `epic-2-context.md` were reconciled (`c993be3`).
- **Risk for Epic 3:** `platform-decisions.md:36` plans the dynamic inventory to read the token "from an env lookup" of `DIGITALOCEAN_TOKEN` — that variable no longer exists, so Story 3.1 built from this decision gets an empty token.
- **SSH keys:** `epics-fantasy-hockey-digitalocean.md:126`, `epic-2-context.md:24`, `platform-decisions.md:18`, `stories.yaml:19`, `SPEC.md:92` still say "both existing SSH keys". As-built injects only `picon___id_rsa.pub` (user decision, `spec-2-4` frozen block; `docs/cloud/digital-ocean/droplet.md`), because the local key and `picon___id_rsa.pub` are the same key.
- **Mount path:** `epics-fantasy-hockey-digitalocean.md:143,212`, `platform-decisions.md:15-16`, `specs/…/epics.md:37` say `/mnt/<volume-name>`; the real path turns hyphens into underscores (`/mnt/prod_fantasy_hockey_data`, user SSH check in `spec-2-5`). Epic 4's data path `/mnt/<volume-name>/fantasy-hockey` inherits the wrong form.
- **Minor:** "name starting with `prod-fantasy-hockey`" (`platform-decisions.md:11`) vs the exact name `prod-fantasy-hockey`; token scope names in the planning docs (`volume`, `reserved IP`) vs the doc table (`block_storage`, `reserved_ip`, plus `actions`).
- **Disposition:** fix now — spec reconciliation, proposed (action item 1).
- **Lesson:** a story decision that changes a planning fact must reconcile every planning doc in the same change, not only the epics file and the epic context.

### 2. The token delivery chain broke silently across stories (verification gap, edge case)

- **Source:** `a12d7ff` (Story 2.2) renamed the export in `ansible/playbooks/desktop.yml:25` but not the devcontainer's `localEnv`; the chain stayed broken until `6f8671f`, and only the Story 2.3 docs review noticed (`spec-2-3` Review Triage Log). No check covers the chain (no assertion in Molecule, InSpec or a post-create hook).
- **Still open:** `configs-homelab/ansible/tasks/bash-secrets.yml` removes only `GITHUB_METRICS_EXPORTER_TOKEN` as obsolete, so `export DIGITALOCEAN_TOKEN=<old token>` stays in every existing `.bashrc`; and `lineinfile` without `regexp` appends a second `DIGITALOCEAN_ACCESS_TOKEN` line when the token is rotated instead of replacing the first.
- **Disposition:** fix now (action item 3). The missing check of the chain: defer.
- **Lesson:** renaming a variable that crosses tools (vault → playbook → `.bashrc` → `containerEnv`) needs one grep over all consumers in the same commit.

### 3. Host OpenTofu is unpinned while `required_version` is exact (edge case, cross-story)

- **Source:** `configs-cloud/digital-ocean/opentofu/versions.tf:2` (`required_version = "1.12.7"`, Story 2.4); the submodule bump `8713787` installs `opentofu` and `doctl` on workstations via snap/pacman without a version (`ansible-roles-collection/packages/tasks/main/10-basics.yml:35-39,75-80`); `docs/cloud/digital-ocean/droplet.md:142` sends users to the host as a fallback; `api-token.md:47` says "the 1.12.x line", which `required_version` does not allow.
- **Failure:** on the host, `tofu` is whatever snap/pacman ships; any version other than 1.12.7 refuses `init`/`plan`.
- **Disposition:** decision needed (action item 4); extends the existing three-pins deferred item.

## Findings

### Spec-to-Implementation Reconciliation

- **R1. Story 9.2 AC 2 is unobserved.** The dashboard reaches Grafana Cloud only through Git Sync from `main`, and PR #389 is not merged. The user marked 9.2 `done` before that (`sprint-status.yaml` comment, `3ae3f38`), against the AGENTS.md pitfall "Never mark a story `done` while an AC depends on a Git Sync from `main`". Disposition: accept the user's decision; open item A1.
- **R2. Story 9.1 AC 2 is checked on 4 of 7 inventory nodes.** pi4-0002, pi5-0004, caprica and picon send all 12 `node_wifi_*` metrics, collector success `1` (spec-9-1 Acceptance Check). pi4-0005, pi4-0006 and kobol did not resolve from the devcontainer and were not checked. No node without Wi-Fi was in reach, so the clause "nodes without Wi-Fi still scrape without collector errors" is backed only by the container test in the spec's Investigation. Disposition: open item A2.
- **R3. Accepted deviation: option B.** The dashboard lives in `homelab-infrastructure` as "Network / Wi-Fi" (12 resources) instead of a new folder `network` (13). The user decided this on 2026-10-23 (spec-9-2 Intent). `epics.md`, `epic-9-context.md`, the PRD and `SPEC.md` were updated in `dc32fa0`. `sprint-change-proposal-2026-10-22.md` keeps "network" as the record of the original proposal. Do not re-flag.
- **R4. Accepted deviation: node variable source.** The variable comes from `node_network_info{device=~"wl.+"}`, not from `node_wifi_station_info` as the 9.2 task said, so a node disconnected for the whole range stays selectable (spec-9-2 triage, `dc32fa0`). The spec's Tasks line still names the old source (code review, rejected because the fix edits the spec). Do not re-flag.
- **R5. Spec status vs sprint status.** Both specs got `status: 'done'` from `bmad-build` while sprint status held both stories in `review` (flagged by three code-review layers). That is the build workflow's convention (spec done = built and reviewed), not a defect. Accept.

What worked.** Read-only SSH from the devcontainer to the fleet nodes was re-tested at the start of the epic, as the AGENTS.md pitfall asks, and turned the 9.1 fleet check into an agent check. The duplicate dashboard name `000000013` from `6813c9f` was caught in review and removed before merge (`5694b1e`).

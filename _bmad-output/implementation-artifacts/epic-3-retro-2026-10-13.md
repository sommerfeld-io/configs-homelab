## Findings

### Cross-story interactions (no single session saw both sides)

1. **Fleet-only side effects land on the public droplet (3.2 × 3.3).** Provisioning reuses the whole fleet `grafana-cloud/alloy` role. Checked read-only on the droplet:
    - `/etc/alloy/github.token` (the fleet GitHub token) is present.
    - `/usr/bin/alloy` has `cap_net_raw,cap_sys_ptrace,cap_sys_admin=ep`, and the systemd override grants the same ambient capabilities.
    - On every provision, the fleet config briefly runs on the droplet before `alloy-config` replaces it. That config includes `remotecfg` with the homelab fleet-management collector `id = "8a0ba9569295"` (`configs-homelab/ansible/roles/grafana-cloud/alloy/templates/config.alloy.j2:1-3`).
    - If `alloy-config` fails or the run is cut off, the fleet config stays live.
    - Sources: adversarial 1, 2 and 4; verification-gap 2 and 5; edge-case "remotecfg".
    - Disposition: **fix now (decision needed)**. This is the known cost of the cloud-owned config you chose in 3.2, but the GitHub token, the capabilities and the fleet-management registration were never part of that trade-off.
    - Prevention: when a story reuses a whole fleet role on a cloud host, list every side effect of that role in the spec, not just its main output.
2. **During that window the droplet sends `environment=digital-ocean` without `stage` (3.2 × 3.3).** The fleet template has no `stage` label, so for those seconds the droplet's series split into a version without `stage` and a version with `stage=prod` (adversarial 3). Disposition: **accept**. It is resolved by item 1 if the window goes away.
3. **`alloy-config` depends on facts that only the fleet role sets.** It reads `alloy_config_dir`, `alloy_group` and `alloy_service_name`, which the fleet role sets with `set_fact`. `alloy-config` has no defaults of its own (`configs-cloud/digital-ocean/ansible/roles/alloy-config/tasks/main.yml:8-19`, `handlers/main.yml:4`). ## Addendum: Story 3.5 Host Session Losses (2026-10-13)

Added after the retrospective, when Story 3.5 was built.

- **What happened:** the first Story 3.5 design ran the Molecule scenarios in a privileged `ubuntu:26.04` container with systemd as PID 1, `cgroupns_mode: host` and the host's `/sys/fs/cgroup` mounted read-write. While it ran, the desktop session on picon (the omarchy host running the devcontainer and this Claude Code session) died three times: 20:16:36Z, 20:20:43Z and 20:31:02Z. Each time the screens stayed black, the user rebooted, and the reboot killed the Molecule run and the agent session.
- **Root cause (Grafana Cloud AI analysis of picon's logs, medium to high confidence):** no kernel crash. Each loss started with a systemd booting inside a container (kernel core dump for `systemd-sysctl` as PID 31, a PID that only exists in a container). About one second later the host's tty1 session got SIGHUP and stopped Hyprland. SDDM then failed with `Failed to take control of "/dev/tty1" ("root"): Operation not permitted` until `start-limit-hit`. A privileged container sees the host's `/dev`, so a console unit started by the container's systemd (most likely a getty on tty1, not directly observed) took the host's tty1. The 20:31:02Z loss matches the Molecule container start at 20:31:01Z. A VS Code core dump on the host at 20:01:28Z may be a fourth loss from a short privileged systemd probe the agent ran earlier (unconfirmed).
- **Agent mistake:** the agent wrote "the host rebooted" and blamed shared cgroups into the docs and agent instructions without logs. The logs did not support the cgroup explanation; the reboots were the user's recovery actions. Corrected in `docs/cloud/digital-ocean/tests.md`, `.github/copilot-instructions.md`, the epics file and `deferred-work.md`.
- **Resolution:** human decision to keep tests simple and never break the host. The cloud scenarios run in plain unprivileged containers without systemd or host mounts; a `systemctl` stub answers the Alloy role, and the `swap` role has no scenario (`swapon` needs a privileged container, recorded in `deferred-work.md`). Both lessons are now pitfalls in `AGENTS.md`.

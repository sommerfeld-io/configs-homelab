## Known pitfalls

- Run every command a doc shows once before committing the doc, and quote errors from real output. Agents wrote `doctl --format …Size` (the column is `SizeSlug`), a paraphrased `Instance cannot be destroyed` error (the real text is `Resource instance cannot be destroyed`), and a guessed mount path (`/mnt/prod_fantasy_hockey_data`, not `/mnt/<volume-name>`).
- When a decision changes a planning fact, update every planning doc in the same change: `SPEC.md`, `platform-decisions.md`, `stories.yaml`, the epics files, `epic-N-context.md` and the architecture. Updating only the epics file left three docs naming the wrong token variable, SSH keys and mount path.
- When a story creates a resource, copy every epic-level constraint on that resource into the story spec's boundaries. "Resize CPU/RAM only, never disk" was missing from `spec-2-4`, so the droplet shipped with the provider default `resize_disk = true`.
- When renaming a variable that crosses tools (vault, playbook, `.bashrc`, devcontainer `containerEnv`), grep every consumer and fix them all in one commit. The `DIGITALOCEAN_TOKEN` to `DIGITALOCEAN_ACCESS_TOKEN` rename broke the devcontainer chain until `6f8671f`.
- Before rejecting a review finding about a third-party default, read that component's source or docs. The 3.1 finding "no `ansible_host`" was rejected on the untested assumption that the DigitalOcean inventory plugin sets it; the first deploy failed with "Could not resolve hostname" until `f3cb231`.
- Never write a timestamp by hand (`last_updated` in `sprint-status.yaml`, dates in specs): take it from `date '+%m-%d-%Y %H:%M'` or let `.claude/skills/bmad-retrospective/scripts/sprint_status.py` stamp it. Agents wrote six `last_updated` values ahead of the real time in Epic 3 (`21a9b1e` to `94c60bc`).
- Re-test an environment limit at the start of each epic instead of copying it from an earlier spec or retro. "Agent SSH to the droplet is blocked" was carried into the 3.1 and 3.2 specs and pushed checks onto the user, while read-only `ssh root@<droplet-ip>` from the devcontainer works. Only runs that need the vault password are user-run.
- Before writing what code does into an option, spec or doc (a cause, a side effect, a change count), check it in the code or a real run. Agents described a 3.2 option wrong before approval, gave "forced template" as the cause of the per-run Alloy change, and documented four changing tasks where the second provision run showed six.
- Never run a privileged container, a container with systemd as PID 1, or one with host mounts, not for tests and not for a quick probe. This session runs in a devcontainer on the operator's desktop host (picon). In Story 3.5 a privileged systemd Molecule container reached the host's `/dev/tty1`: each time its systemd booted, the desktop session got SIGHUP and the screens stayed black until the user rebooted, three times. Use unprivileged containers and stub what needs privileges (`systemctl` stub in `configs-cloud/digital-ocean/tests/molecule/prepare.yml`), or skip the test.
- Never write a guessed cause for a host or infrastructure failure into docs, specs or commits. Ask the user for logs first: picon's journal and kernel logs are in Grafana Cloud (Loki). In Story 3.5 the agent documented "the host rebooted" and blamed shared cgroups; the logs showed no crash, but a tty1 hangup followed by the user's recovery reboots.
- Run a drill before writing its procedure doc, then write the doc from what the run showed. `docs/cloud/digital-ocean/replacement.md` was written and reviewed (18 findings) before the Story 4.3 drill, then rewritten and cut down to a short page in three commits (`678264f`, `6d0ef57`, `651a8e8`).
- Check what the public sees (HTTP answers, `/metrics` 404, closed ports) at the reserved IP from `tofu -chdir=configs-cloud/digital-ocean/opentofu output reserved_ip_addresses`, never at the droplet's own IPv4, which changes with every replacement. Story 4.1 was checked at `164.90.238.181`, so the reserved IP the AC names was first verified in 4.3.
- Never assume DigitalOcean mounts a volume: it mounts one automatically only when the volume and the droplet are created together. A replacement droplet gets the existing volume attached but not mounted, which is why `deploy-fantasy-hockey.yml` mounts it. `droplet.md` claimed otherwise until drill run 1 stopped at the mount guard (`6d0ef57`).
- When a story is built inside another spec, still give it its own acceptance check against its ACs and its own review triage log. Story 5.2 was built inside `spec-grafana-cloud-synthetic-monitoring-in-opentofu.md` (oneshot, no triage log), so its 21-file commit `0368e1a` got its first review in the Epic 5 retro.
- Never mark a story `done` while an AC depends on a Git Sync from `main` or a deploy that has not happened yet; leave it in `review` and list the sync or deploy check for the user. Stories 5.1 and 5.3 were marked `done` with no Epic 5 commit on `main`, so their dashboard ACs were never observed (Epic 5 retro, finding 1).
- Route work that closes a deferred item or part of a later story through a story or spec with its own review, even small CI work; at the least, update `deferred-work.md` and that story in the same change. `63fabb4`, `3e90479` and `a96b137` added `tofu validate` to `task lint` and CI between Epic 8 story commits without either: `deferred-work.md` and Story 6.1 kept listing the work as open until `688345c`, and the unreviewed commits broke `task lint` in any checkout without `tofu init` until `6da3d31` and left the CI job with a hand-kept root list (Epic 8 retro, findings A2, R1 and R2).
- When you write or review a runbook step that waits, name the observable check that shows the wait has done its job, and gate the next step on that check, not on the elapsed time. `dns-delegation.md` M13 said "wait at least 4 hours (2 × the KAS TTL of 7200 s)", its reason ("every resolver has expired the KAS answers") could not be observed, and M14 was gated on "M13's wait has passed"; the operator deleted the KAS record 4 minutes after adding the NS records because both KAS nameservers already returned a referral (Epic 8 retro, finding A1).
